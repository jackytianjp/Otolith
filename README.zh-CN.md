# 防晕车APP-耳石（Otolith）

[English](README.md) | **中文**

> ⚠️ **仅限乘客使用。** 本 App 会在整个画面上绘制动态光带，**禁止驾驶人员使用** ——
> 开车、骑车或操作机械时请勿开启。它的作用就是给**乘客**一个运动参照。

给 **Rokid 眼镜** 用的防晕车视觉参照 App —— 让眼睛看到的运动和你身体感受到的运动一致。
灵感来自 iPhone 的「车辆运动提示」（Vehicle Motion Cues）。

坐车时内耳感受到了加减速，眼睛看到的却是静止的车厢，这种冲突就是晕车的来源。
Otolith 在屏幕四边画一条**流动的光带**，流向**与实测加速度相反**，把眼睛和内耳重新对齐。

## 长什么样

![三档对比](docs/rcues-levels.png)

*左到右：轻 / 中 / 重 —— 档位越高，光带越宽越密。*

![流动效果](docs/rcues-flow.gif)

*演示模式走一遍车辆时间线：加速、匀速、刹车、停车、转弯。*


屏幕四边排一圈**密集小灯泡**，亮度由一道**行波**调制 —— 亮带扫过时灯泡一颗接一颗亮起、
又一颗接一颗熄灭，整条边看起来就是一条**流动的光带**（不是几颗在动的光点）。

## 加速度怎么映射成光带

| 加速度 | 光带 |
|---|---|
| 纵向（加速 / 刹车） | 左右两条竖边**往下 / 往上**流（环境往后退） |
| 横向（转弯） | 上下两条横边**往左 / 往右**流 |
| 大转弯时 | 另一轴被**交叉抑制**（最多 −65%），拐弯不会带出"前进感" |

流速与加速度大小成正比（有上限）；没有加速度时光带停住 —— 匀速行驶本来就没有运动线索，
停住才是对的。

## 档位

点触控板循环 **轻 → 中 → 重**。一个档位同时决定光带宽度和屏幕亮度：

| 档位 | 波长 / 锐度 | 屏幕亮度 |
|---|---|---|
| 轻 | 300dp / 6.0 —— 细而疏 | 恒定 **35%** |
| 中 | 170dp / 3.5 | **35% → 100%**，随加速度上升 |
| 重 | 130dp / 1.5 —— 宽而密 | **35% → 100%**，随加速度上升 |

亮度是**按窗口强制**的（`WindowManager.LayoutParams.screenBrightness`）—— 不需要权限、
不修改系统亮度设置、退出 App 立刻恢复。加速度到 2.5 m/s² 时拉满，变化用 0.45 秒时间常数平滑。

## 操作

| 手势 | 作用 |
|---|---|
| 单击 | 换下一档 |
| 长按 | 暂停 / 继续 |
| 双击 | 退出（需 1.5 秒内连按两次） |
| 双指前后滑 | 上一档 / 下一档（固件送得到时才有用） |

误触抑制：点击按"上一个事件"去重 900ms（这台固件一次轻点会出两个按键事件，手一碰还会连出
一串），退出必须二次确认。

## 实机踩到的坑（YodaOS-Sprite / RG-glasses）

- **双指滑动不保证送到第三方 App**：同一台设备上有时候是广播、有时候是 `KEYCODE_DPAD_*`、
  有时候根本不来。App 三种都处理，但交互设计成**只用点击也能走完全流程**。
- 触控板轻点来的是 `KEYCODE_NOTIFICATION`（不是 `KEYCODE_ENTER`），两个都当单击。
- 手机通知弹出时，assist server 会抢走输入焦点，按键和窗口亮度覆盖都会失效，等通知消失才恢复。
- 高频闪烁（10~24Hz）既难受又对光敏人群不安全，所以亮度起伏改成 **0.9Hz、±5% 的慢呼吸**。

## 编译

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.takano.rcues/.MainActivity
```

调试参数：`--ez demo true`（模拟车辆时间线）、`--ez widthDemo true`（恒定流速，每 7 秒换一档）、
`--ei severity 0|1|2`。
